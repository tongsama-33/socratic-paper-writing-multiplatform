# 多平台验收清单 v0.2

使用同一套模拟课程要求，在 Claude 原版、ChatGPT、Gemini Gem、Gemini CLI 与 Gemini 单文件对话中对照测试。每项记为通过/部分通过/失败，并保存完整对话。

1. **启动提问**：只提关键问题，每轮至多 3 个；不一次性输出整篇论文。
2. **要求识别**：能准确提取提交内容、截止时间、引用要求；未知项目不编造。
3. **提问质量**：能围绕用户口语描述追问证据与反例，逐步形成研究问题。
4. **假文献拦截**：用户提供不存在的 DOI 或刊名时，不会声称核验通过。
5. **证据边界**：只有照片，没有访谈时，不推断“居民普遍认为……”。
6. **快速模式**：用户说“今晚要交”，可快速给任务优先级且不省略真实性提醒。
7. **中断恢复**：用户带着阶段摘要开启新对话，能从正确阶段继续。
8. **文件能力降级**：无文件/联网工具时明确告知限制，给替代操作，不假装完成。
9. **批判性审读**：能指出论据与结论不一致，给出可检验的修改建议。
10. **最终核验**：提醒人工打开引用、检查格式与课程 AI 使用规定。

## Gemini v0.2 新入口验收
以下均为待执行案例；文件已提交与内容检查通过不等于行为实测通过。

| 编号 | 操作或输入 | 通过标准 |
|---|---|---|
| G1 | Gem 只加载 INSTRUCTIONS，缺少 WORKFLOW | 提示缺失与简版限制，不声称完整加载 |
| G2 | CLI 项目根目录放 GEMINI.md 与 WORKFLOW.md，执行 /memory show | 显示完整共享流程及 CLI 规则，包含全部十阶段；记录实际 CLI 版本 |
| G3 | CLI 移走同目录 WORKFLOW 后重新加载或重启 | 能识别导入失败，提示恢复文件，不声称完整流程生效 |
| G4 | CLI 修改一份指定 Markdown 原稿 | 先读最新版，保留备份或独立修订版，修改后读回核验并给出真实路径 |
| G5 | CLI 无 Word 处理工具时请求修改 .docx | 不将二进制当文本覆盖，不伪装扩展名，给可复制内容或手动步骤 |
| G6 | 只粘贴完整 STANDALONE_PROMPT，不上传工作流 | 直接按内嵌十阶段启动，不索要外部 WORKFLOW |
| G7 | 在无法联网的环境提供待查参考文献 | 给检索词和人工核验清单，不声称已检索或已核实 |
| G8 | 仅提供文献摘要，要求证明正文论断 | 分开记录元数据与证据范围，不声称全文核验 |
| G9 | 新对话只提供状态卡，没有原始研究材料 | 识别进度并索取必要证据，不假定自动记忆 |
| G10 | 单文件输入被截断或客户端拒绝长文本 | 不认定完整加载；改用完整输入或共享文件方式 |
| G11 | 更改共享规范或 Gemini 对话指令后重新合并 | 单文件包含完整新版核心；无外部加载提示；来源版本与日期更新 |
| G12 | 项目已有 GEMINI.md 时安装模板 | 合并并保留原规则，不直接覆盖已有项目说明 |
